## 为什么改成 Fly 了还是跑 TestDialogue

你改的是代码第 47 行 `= "Fly"`，但场景文件里存着 `dialogueFileName: TestDialogue`。规则是这样的：

| 位置 | 作用 |
|---|---|
| 代码里的 `= "Fly"` | 只是**初始值**：组件第一次挂到物体上时用一次 |
| Inspector 里显示的值 | 挂上以后就存进场景文件，**之后一直以它为准** |

## 贝塞尔的原理（跟 CSS 的 `cubic-bezier` 完全一样）

| 概念 | 意思 |
|---|---|
| 四个值 `(x1, y1, x2, y2)` | 两个控制点。起点固定在 (0,0)，终点固定在 (1,1) |
| 横轴 x | **时间**进度（0 到 1） |
| 纵轴 y | **动画**进度。y1、y2 可以超出 0~1，比如 1.56，那就是**过冲**：冲过头再弹回来 |
| 难点 | 我们手上有的是时间 x，但贝塞尔公式是用参数 u 同时算出 x 和 y。所以要先反推出「哪个 u 正好对应这个 x」，再用这个 u 算 y。反推用的是二分法：在 0~1 之间对半猜 20 次，精度到百万分之一 |

反推那部分是纯数学，不是你这阶段要练的，直接贴进你的 `Tweens.cs` 就行（放在 `EaseOut` 下面）：

```csharp
    // CSS 同款 cubic-bezier(x1, y1, x2, y2)：返回一条曲线，可以直接当 ease 传给 Tween
    // y1、y2 超出 0~1 就会过冲。例：Bezier(0.34f, 1.56f, 0.64f, 1f) 冲过头再回弹
    public static Func<float, float> Bezier(float x1, float y1, float x2, float y2)
    {
        return t =>
        {
            // 已知时间进度 t，用二分法反推贝塞尔参数 u（x 随 u 单调增加，所以一定能夹逼到）
            float lo = 0f, hi = 1f, u = t;
            for (int i = 0; i < 20; i++)
            {
                u = (lo + hi) * 0.5f;
                if (Axis(u, x1, x2) < t) lo = u; else hi = u;
            }
            return Axis(u, y1, y2);   // 用同一个 u 算出动画进度
        };
    }

    // 三次贝塞尔在一个轴上的值（起点 0、终点 1，中间两个控制点 p1、p2）
    static float Axis(float u, float p1, float p2)
    {
        float v = 1f - u;
        return 3f * v * v * u * p1 + 3f * v * u * u * p2 + u * u * u;
    }
```

新概念只有一个：**返回一个函数的函数**。`Bezier(...)` 本身不做动画，它做出一条曲线交给你，你再把这条曲线递给 Tween。

**过冲为什么能成立**：你 Tween 里的 `Mathf.Clamp01` 只夹住了**时间**（elapsed / time），没有夹住曲线的**输出**。所以 y 冲到 1.1 也能原样传给 `onUpdate`。要是把 Clamp 放在输出上，过冲就被削平了。这一点很关键。

**常用的几组数，可以直接抄：**

| 用途 | 写法 |
|---|---|
| HTML 原型的入场（极致缓出） | `Tweens.Bezier(0f, 0f, 0f, 1f)` |
| HTML 原型的退场（极致缓入） | `Tweens.Bezier(1f, 0f, 1f, 1f)` |
| 冲过头再回弹 | `Tweens.Bezier(0.34f, 1.56f, 0.64f, 1f)` |
| CSS 默认的 ease-out | `Tweens.Bezier(0f, 0f, 0.58f, 1f)` |

想调手感，可以去 cubic-bezier.com 拖控制点，看到满意的再把四个数抄回来。比 Unity 自带的曲线编辑器好用，这个你之前抱怨过。

## ① `Func<float, float>` 为什么就是曲线？

你说得对，曲线是二维的，需要两个值。`Func<float, float>` 里**正好就是这两个值**：

| 写法 | 意思 |
|---|---|
| `Func<float, float>` | 「一台机器：放进去一个 float，吐出来一个 float」 |
| 第一个 float | 放进去的：**横轴 x**，也就是时间进度 |
| 最后一个 float | 吐出来的：**纵轴 y**，也就是动画进度 |

一条曲线，数学上本来就是 `y = f(x)`：给任意一个 x，算出对应的 y。我们不需要把整条曲线画出来存着，只要有一台「给 x 就算出 y」的机器，任何时候问它都行：

| 问它（时间走到） | 0 | 0.25 | 0.5 | 0.75 | 1 |
|---|---|---|---|---|---|
| 线性 `t => t` 答 | 0 | 0.25 | 0.5 | 0.75 | 1 |
| 过冲贝塞尔答（大约） | 0 | 0.75 | **1.08** | 1.04 | 1 |

所以 `Bezier(0.34f, 1.56f, 0.64f, 1f)` 那四个数**不是**曲线本身，它们是「造这台机器用的图纸」：决定曲线长什么样。`Bezier` 照着图纸造好机器，再交给 Tween。

顺便对比一下：`Action<float>` 是「放进去一个 float，**什么都不吐出来**」，只负责做事；`Func` 一定会吐出一个值。

**写法 C（你那两行）：连方法都不单独写**，用 `p => ...` 当场写一个没有名字的小方法（lambda）。`p =>` 左边是它收到的参数，右边是它要做的事，跟写法 A 的 `MoveNamePlate` 一模一样，只是省掉了名字。

**Tween 拿到这三样东西以后，每一帧都这样走一遍：**

| 帧 | elapsed | t = elapsed / 0.4 | 曲线（Bezier 那台机器） | 你那段代码收到 p，执行 | 名牌 x |
|---|---|---|---|---|---|
| 开始 | 0 | 0 | 0 | -24 × (1 - 0) | -24（在左边） |
| … | 0.1 | 0.25 | 约 0.75 | -24 × (1 - 0.75) | 约 -6 |

| … | 0.3 | 0.75 | 约 1.04 | | 约 +1 |
| 结束 | 0.4 | 1 | 1 | -24 × 0 | 0（停稳） |

（中间几行的曲线值是估的，看趋势就好。）

分工就是这样：

| 谁 | 负责什么 |
|---|---|
| Tween | 计时，每帧算出 t |
| 曲线 | 把 t 变成「加了手感」的 p |
| 你那段 `p => ...` | 拿 p 去改东西：这次改位置，换一段代码就能改透明度、大小、颜色 |

## 一、Tween 逐行讲

```csharp
public static IEnumerator Tween(float time, Func<float, float> ease, Action<float> onUpdate)
```

| 部分 | 意思 |
|---|---|
| `public static` | 哪里都能直接用 `Tweens.Tween(...)` 来调用，不用先挂到物体上 |
| `IEnumerator` | 说明它是**协程**，可以「做一点 → 停一帧 → 接着做」。你的 FadeVolume 也是这个开头 |
| `float time` | 动画一共多少秒 |
| `Func<float, float> ease` | 曲线机器：给它时间进度，它还你动画进度 |
| `Action<float> onUpdate` | **你递进来的那段代码**：每帧拿到进度后，具体去改什么 |

```csharp
    float elapsed = 0f;
```
秒表清零：已经过去了 0 秒。

```csharp
    while (elapsed < time)
    {
```
只要时间还没到，就一直循环。每转一圈就是一帧。

```csharp
        elapsed += Time.deltaTime;
```
秒表加上「这一帧过了几秒」。

```csharp
        float t = Mathf.Clamp01(elapsed / time);
```
换算成 0~1 的时间进度。比如总长 0.4 秒、已过 0.1 秒，t 就是 0.25。`Clamp01` 防止最后一帧算出 1.03 这种超出的值。

```csharp
        onUpdate(ease(t));
```
这一行是整个方法的核心，要从里往外读：

1. `ease(t)`：把时间进度 0.25 交给曲线机器，拿回动画进度，比如 0.75
2. `onUpdate(0.75)`：把 0.75 交给**你递进来的那段代码**，让它执行一次。也就是你的 `MoveNamePlate(0.75)` 在这一刻真正跑了，名牌被挪到 x = -6

```csharp
        yield return null;
    }
```
这一帧的活干完了，停在这里，**下一帧再从这里接着跑**，回到 while 开头。跟 FadeVolume 里的完全一样。

```csharp
    onUpdate(ease(1f));
```
循环结束后再补一次「进度正好是 1」，保证名牌精确停在终点。否则最后一帧可能停在 0.98 这种位置。

**整体作用**：在 `time` 秒里每帧算一次进度，进度先过曲线，再交给你的代码去用。至于「用」是挪位置、调透明度还是改颜色，Tween 一概不管。

## 二、「递过去」和「现在就执行」

打个比方：

| 写法 | 比喻 | 实际发生什么 |
|---|---|---|
| `MoveNamePlate(0.5f)`（有括号） | 你**现在**自己炒好一盘菜 | 立刻执行一次，名牌马上跳到 0.5 的位置，就结束了 |
| `MoveNamePlate`（没括号） | 你把**菜谱**交给厨师 | 现在什么都不发生。厨师（Tween）每一帧照着菜谱做一次，每次放进不同的进度值 |

Tween 要的是**菜谱**：它要在 0.4 秒里、每一帧、用不同的 p 去调用你的方法，可能调用二三十次。所以只能把方法本身交给它，不能先执行。

如果你写成 `Tweens.Tween(0.4f, curve, MoveNamePlate(0.5f))` 会直接报错：`MoveNamePlate(0.5f)` 执行完什么都不返回（void），等于你递过去一盘「空气」，Tween 没东西可调用。

## 三、`StartCoroutine(Tweens.Tween(0.4f, curve, MoveNamePlate));`

还是从里往外读：

| 步骤 | 发生什么 |
|---|---|
| ① `Tweens.Tween(0.4f, curve, MoveNamePlate)` | 只是**准备好**一个协程：时长、曲线、菜谱都装进去了，但一行都还没跑 |
| ② `StartCoroutine( … )` | 按下开始键，Unity 从这一帧起每帧推它往前走一步，碰到 `yield return null` 就等下一帧 |

## 四、把整件事按时间串起来

| 时刻 | 发生什么 |
|---|---|
| 某一行台词换了说话人 | 你的代码执行到 `StartCoroutine(...)`，Tween 开始跑 |
| 第 1 帧 | elapsed 约 0.016 → t 约 0.04 → 曲线给出 p → 调用 `MoveNamePlate(p)` → 名牌挪一点 → yield，等下一帧 |
| 第 2、3……帧 | 一样的流程，p 越来越大，名牌越来越接近原位（中途冲过头一点） |
| 约 0.4 秒后 | while 结束 → 最后补一次 `MoveNamePlate(1)` → 名牌停在 0 → 协程结束 |

**这一切进行的同时**，你的打字机、点击等待照常在跑，因为它们是各自独立的协程，互不阻塞。

## 填空题：章扉页的进出场

骨架脚本 `ChapterCard.cs` 我已经写好、编译通过了。数据、往里填文字、怎么摆 12 栏的那些辅助方法都在里面。你只需要写最后两个协程：`Cover`（进场）和 `Reveal`（退场）。

**表格里的用法**：

| 行 | effect 列 | 发生什么 |
|---|---|---|
| A | `card:ch3` | 12 栏依次落下盖住画面 → 扉页出现 → 停留 |
| B（同一行背景列写新背景） | `uncard` | 扉页收起 → 12 栏抽离，露出**新**背景 |

为什么拆成两行：你的系统是先换这一行的画面、再播这一行的效果。如果写在同一行，背景会在盖住之前就换掉，玩家会看到画面一跳。拆开以后，换背景正好发生在 12 栏把画面盖住的时候。

**能用的辅助方法**（骨架里都有）：

| 方法 | 作用 |
|---|---|
| `SetColumnsAt(秒, true/false)` | 把 12 栏摆到「过了几秒」时的样子。每栏会自动错开 30ms；`true` 是落下，`false` 是抽离 |
| `ColumnsTotal` | 12 栏全部走完一共要几秒 |
| `SetNumeralReveal(p)` | 章号的裁切框从左往右揭开，p 从 0 到 1 |
| `card.alpha` / `card.gameObject.SetActive(...)` | 扉页内容的透明度和显示开关 |
| `holdTime` | 停留几秒（Inspector 里可以调） |

```csharp
    // card:ch3 —— 12 栏落下盖住画面 → 扉页出现 → 停留
    public IEnumerator Cover(string id)
    {
        if (!SetContent(id)) yield break;

        // ① 12 栏落下：秒数从 0 走到 ColumnsTotal
        yield return Tweens.Tween(ColumnsTotal, t => t,
            p => SetColumnsAt(p * ____, true));                        // 空1：p 是 0~1，要换算成秒

        // ② 扉页出现：先显示出来，再淡入；章号从左往右揭开
        card.gameObject.SetActive(____);                               // 空2
        StartCoroutine(Tweens.Tween(0.6f, Tweens.Bezier(0f, 0f, 0f, 1f), p => SetNumeralReveal(p)));
        yield return Tweens.Tween(0.4f, Tweens.EaseOut, p => card.alpha = ____);   // 空3

        // ③ 停留
        yield return new WaitForSeconds(____);                         // 空4
    }

    // uncard —— 扉页收起 → 12 栏抽离，露出新场景
    public IEnumerator Reveal()
    {
        yield return Tweens.Tween(0.25f, t => t, p => card.alpha = 1f - p);
        card.gameObject.SetActive(false);
        yield return Tweens.Tween(ColumnsTotal, t => t,
            p => SetColumnsAt(p * ColumnsTotal, ____));                // 空5：落下还是抽离？
    }
```

| 写法 | 注意 |
|---|---|
| `yield return Tweens.Tween(...)` | **等**这段动画放完再往下走。上次教的子协程，这里第一次真正用上 |
| `StartCoroutine(Tweens.Tween(...))` | **不等**，让它在旁边自己跑。章号揭开和淡入因此是同时进行的 |
| `t => t` | 不加曲线（线性）。12 栏每一栏自己已经带了缓动，外面就不用再加了 |

## `[Header("零件（已经拖好）")]` 是什么

方括号写在字段上面的叫**特性**（Attribute），它是给 Unity 编辑器看的说明，**不影响代码怎么运行**。`[Header("…")]` 的作用是在 Inspector 里加一行粗体小标题，把下面的槽位归成一组，看起来清楚：

```
Chapters        ← 你改文字的地方
▸ 零件（已经拖好）
  Columns
  Card …
▸ 时间
  Column Time   0.45
```

同类的还有 `[TextArea]`（让字段在 Inspector 里变成多行输入框，quote 用的就是它）。你之前见过的 `[System.Serializable]` 也是特性，意思是「这个类可以显示在 Inspector 里」。

## ChapterCard 每个方法在干什么

| 方法 | 干什么 | 打个比方 |
|---|---|---|
| `Awake()` | 游戏一开始执行一次：记下章号框原本多宽，把 12 栏收起来，把扉页藏好 | 开场前先把道具摆回原位 |
| `SetContent(id)` | 在 `chapters` 数组里找到 id 对应的那一章，把章号、章名、引文、页码填进去；目录里当前章反白、没读到的压暗。找不到就警告并返回 false | 换一张印好的扉页 |
| `SetColumnsAt(秒, cover)` | 「过了这么多秒的时候，12 栏各自应该落到哪」：第 i 栏比前一栏晚 30ms 才开始，每栏用 0.45 秒从 0 走到 1。`cover` 为 true 是往下落，false 是往上收 | 按时间翻到动画的某一帧 |
| `SetColumns(值)` | 12 栏一次性摆到同一个高度（只在 Awake 里用来清零） | |
| `ColumnsTotal` | 12 栏全部走完要几秒：0.45 + 0.03 × 11 = 0.78 秒 | |
| `SetNumeralReveal(p)` | 章号裁切框的宽度 = 原宽 × p。p = 0 看不见，p = 1 全露出来 | 拉开一道幕 |
| `Cover(id)` / `Reveal()` | 你写的，用上面这些零件拼成动画 | |

关键的设计思路是：`SetColumnsAt` 和 `SetNumeralReveal` 都只负责「**进度是多少，就摆成什么样**」，自己不计时；计时交给你的 Tween。这跟 Tween 本身的分工是同一个套路：Tween 管时间，`p => ...` 管摆。

// 鼠标移上去：下划线伸出来；移开：缩回去
public class ChoiceButton : MonoBehaviour, IPointerEnterHandler, IPointerExitHandler
{
    public RectTransform underline;
    Coroutine anim;   // 遥控器

    public void OnPointerEnter(PointerEventData e) { Slide(____); }   // 空4：伸到多长？
    public void OnPointerExit(PointerEventData e)  { Slide(____); }   // 空5

    void Slide(float to)
    {
        if (anim != null) StopCoroutine(anim);   // 先停掉旧的，免得两个动画抢下划线
        float from = underline.localScale.x;
        anim = StartCoroutine(Tweens.Tween(0.2f, Tweens.EaseOut,
