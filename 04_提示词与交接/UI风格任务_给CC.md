## 1. 背景

- 项目：DEMO1，国庆要发布的几分钟超短篇视觉小说，标题定为《Fly / 飞》（原工作名《滑翔机》）。
- 故事来自我的一个梦：男孩两次使用滑翔机。第一次起飞，一路飞到地月之间的小行星带，一切梦幻、绚丽、缤纷，紫色蓝色；之后回到地面的片段是怀旧、温柔、褪色的感觉。第二次飞行失败。结尾关于不甘与重新开始。
- 角色：男孩和母亲，都是犬科兽人，日系 kemono 画风（圆润、大眼、偏可爱）。品种未定。
- 美术：背景将来是 AI 生成的**厚涂**风格，人物是**手绘线条感**。这次**不管**角色和背景的画风，只管 UI；原型里用占位即可，**不要画角色**。
- 画布：1920×1080，Unity UGUI（Canvas Scaler 1920×1080）。

## 3. 情绪与优先级（最重要）

- 整体气质：**伤感、宁静、文学性**。
- 当"安静伤感"和"实验张扬"冲突时，**安静伤感赢**。实验感必须克制，是调味，不是主菜。
- 地面 = 怀旧温柔：黄昏、旧照片、暖色、褪色、低饱和。
- 太空/梦境 = 梦幻空灵且绚丽：地月之间的小行星带，紫、蓝为主，透明、发光、缤纷。
- 两种场景是**同一套骨架**，换颜色和材质，不是两套完全不同的设计。

## 4. 风格规范要求

### 4.1 基础方向（已定）

**C 方案：斜切造型 + 半透明玻璃材质 + 切口处发光。**
我看过一个粗糙示意：对话框是轻微斜切的半透明面板，顶边一道发光色线；名字框是倾斜约 3° 的斜切色块；选项按钮是斜切的玻璃条，左侧一道色边，当前项更亮。地面配橙色强调，太空配青/紫强调。这只是方向，**请在此基础上做精、做出设计感**，示意本身太简陋了。

### 4.2 我的个人设计语言

**Y2K Glitch + Swiss Grid + Experimental Typography + New Ugly**，剂量是"均衡"：

| 元素 | 用法 |
|---|---|
| **Swiss Grid** | 全程在的骨架。明确的栅格（请定义列数、边距、基线），严格对齐，大量留白。 |
| **英文/数字装饰排版** | 允许并鼓励：如 `SCENE 02`、坐标、编号、时间码等，作为 Swiss 风格的排版元素。尽量让它们承载真实信息（场景号、选项编号等），不要纯堆砌。 |
| **Experimental Typography** | 主要用在标题、转场、章节卡，正文保持克制易读。 |
| **Y2K Glitch** | **爆发点**：转场、标题、菜单。**全程只保留细微**的存在：轻微噪点、偶尔的 RGB 错位、扫描线感。对话进行中不能干扰阅读。 |
| **New Ugly** | 刻意的不完美，极少量：比如一个故意偏离网格的元素、原始感的标签。要克制。 |

### 4.3 色彩

为地面和太空各定义一套色板（背景基调、面板、文字、强调色、发光色、glitch 用的错位色），给出 hex。两套之间要有关系（同一骨架、同一层级逻辑）。注意文字可读性。

### 4.4 字体

- 标题：**衬线**中文（如思源宋体 / Noto Serif SC 这类）。
- 正文：**黑体**，项目目前用 HarmonyOS Sans SC，已做成 TMP 字体图集，**优先沿用**。
- 英文/数字装饰：提议 2–3 款无衬线或等宽字体供我选。
- **所有字体必须可免费商用**，写明授权（如 SIL OFL）。
- 中文字体在 Unity 里要逐个生成 TMP 字体图集，所以**中文字体总数尽量少**（最好标题 1 款 + 正文 1 款）。

### 4.5 动效

我偏向**平面 MG 动画**的感觉：**整体很快，但缓动极致**——动作在一瞬间冲出去，再用很长的尾巴慢慢停稳。

- 入场：`cubic-bezier(0, 0, 0, 1)`（极致缓出）
- 退场：`cubic-bezier(1, 0, 1, 1)`（极致缓入）
- 可以在这两条基础上微调，但保持这种"极端"的性格。
- Glitch 时刻：叠加闪烁、错位、撕裂，节奏突然变碎。
- 请定义动效 token：几档时长、几条曲线、各自用在哪。

### 4.6 标题

- 主标题只用一个字：**「飞」**，做实验性字体处理，这是全作最大的排版时刻。
- **"Fly"** 小字放在**右下角**做点缀。
- 标题界面是 Glitch 爆发点之一。

## 6. 毛玻璃对比

HTML 的 `backdrop-filter: blur()` 一行就能做毛玻璃，但 Unity UGUI 原生做不到，需要 shader。请在原型里**并排展示**两种方案，并在规范里写对比：

| 方案 | 说明 |
|---|---|
| 假玻璃 | 半透明 + 噪点纹理 + 发光边，不做真模糊 |
| 真模糊 | 背景实时模糊 |

对每种写清楚：视觉差多少、Unity 里怎么实现、要不要写 shader、我的项目渲染管线下是否可行（先查一下项目用的是哪条管线）、性能、学习成本。可以说你倾向哪个，**由我决定**。

## 7. UNITY_NOTES.md

对每个组件写：
- 在 UGUI 里用什么拼（Image、九宫格 Sprite、Mask、TextMeshPro、材质……）
- 哪些 CSS 效果在 UGUI 里**没有直接对应**，打算怎么替代（列出来，别藏）
- 哪些动效适合原生做（Animation / 协程 / DOTween），哪些适合**用 HTML 渲染成视频**再用 VideoPlayer 播放（比如 Glitch 转场、标题动画；视频可考虑带透明通道的 WebM）
- 需要导出哪些图片素材、尺寸多少

原型设计时就要**考虑能不能翻译进 UGUI**：能用九宫格和简单形状实现的优先；依赖某个 CSS 特性才能成立的设计，标出来。
